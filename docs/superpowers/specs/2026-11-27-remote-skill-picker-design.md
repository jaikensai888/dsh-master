# dsh-master 远程 Skill 选择器设计

## 用户操作

在远程会话输入框开头输入 `/`，打开当前会话可调用的 Skill 列表。继续输入名称前缀可筛选。条目显示 Skill 名称和描述。选择后将草稿补为 `/技能名 `，保留已有参数和后续正文，焦点回到输入框。用户确认发送后，远端会话按原有机制加载 Skill。

鼠标可以选中条目。键盘用上下键浏览、Enter 选中、Esc 关闭。菜单关闭后，输入框继续按现有规则发送消息和换行。中文输入法选词期间，按键交给输入法。目录加载失败、为空或节点不支持时，给出对应提示，普通消息仍可发送。

## 方案与范围

通过 dsh-master 服务代理目标节点的 `skills/list`，按 `nodeId` 和 `sessionId` 查询。目标会话的工作目录与 Agent 预设决定目录内容。通过原有远程消息接口发送 `/技能名`，由远端宿主识别并加载。保持原有远程发送开关、排队与插话行为。首版覆盖远程会话的 Skill 发现和选择。技能安装、同步、编辑及本机代执行另行设计。

只请求目录元数据。旧节点不提供 `skills/list` 时保留现有手动输入行为。会话切换后取消旧请求并丢弃迟到结果。

## 已核对的依据

- DSH 上游目录接口 `skills/list` 按会话查询用户可调用的 Skill，入参为 `{ request: { sessionId } }`。其中 `modelInvocable: false` 表示可由用户选择，Agent 不会自行发现并调用。
- DSH 上游选择器的选中行为是插入 `/技能名 `。宿主的 Skill 工具会在执行前识别用户消息中的调用标记。dsh-master 远程消息已经可以传递该文本。
- 当前运行的本地 DSH 安装包包含上述目录和加载能力。此前从实际远程会话快照看到了 Skill 加载记录。目标节点的目录接口及从 dsh-master 输入框触发的新一轮调用，需要按实施计划单独验收。
