## 1. 用户决策与本期边界

用户选择了截图中的紧凑汇总卡片样式：深色圆角容器，顶部图标及汇总信息，分隔线，下方多行文件，底部“全部 N 个文件”展开入口。最终参考图为本文件同目录下的 `2026-10-31-remote-delivery-summary-card-reference.png`。此前生成的三张独立大卡片效果图已被此参考取代。

用户要求先设计交付卡片，后续再考虑文件打开问题，并要求提供文档与 prompt 交由其他 Agent 开发。

本期交付：将已有远程会话产物区域改为一个紧凑汇总卡片，保留真实产物下载链路。

不包含：工作区文件树、代码修改统计卡片、从消息解析路径、自动登记所有生成文件、预览、编辑、自动打开、本机应用调用、批量下载，以及 node/coordinator 协议扩展。不修改原会话正在处理的节点选择器、远程会话新建和归档功能。

以下是设计方采用的实施默认值，用户未逐项确认；实施者可在不改变功能边界的情况下微调排版：

- 先沿用现有会话级位置：消息区域之后、输入框之前。用户最后的“ok”不作为逐条回复绑定的明确确认；当前协议也缺少可靠的回复/回合关联字段。
- 默认显示前 4 个文件，可展开与收起。
- 仅展示真实 `listArtifacts` 元数据，不伪造交付结果。
- 为减少回归，保留现有 `mergeArtifacts` 的创建时间升序与按 ID 去重语义；本期不改全局排序。

## 3. 视觉结构

```text
┌──────────────────────────────────────────────────┐
│ [文件图标] 已交付 6 个文件                         │
│            共 3.2 MiB                            │
├──────────────────────────────────────────────────┤
│ 文件展示方案.docx             128 KiB    ↓ 下载   │
│ 需求评审记录.pdf               2.4 MiB    ↓ 下载   │
│ 功能拆分与工时估算.xlsx         86 KiB    ↓ 下载   │
│ 接口说明.md                     12 KiB    已过期   │
│                                                  │
│ 全部 6 个文件 ⌄                                  │
└──────────────────────────────────────────────────┘
```

上图为示例数据，不是待写入产品的静态内容。标题、总大小和行数来自真实会话产物；例如 6 个产物中 2 个失效，标题仍为“已交付 6 个文件”，总大小为全部登记产物的 size 总和，不暗示全部可下载。

- 外框：复用宿主主题背景、边框和文字变量；参考图为深色效果，浅色主题也必须可读。不硬编码整页黑底。
- 圆角建议 12px，1px 细边框，无渐变、大阴影或独立大按钮。
- 头部：左侧约 36–40px 图标容器，右侧标题约 13–14px，次行总大小约 11–12px。不要照搬参考图的绿色/红色增删行数字。
- 顶部分隔线只出现一次。列表行高度建议 32–36px，左右内边距约 14px；文件名占可伸缩宽度，右侧大小和操作保持对齐。
- 文件名单行省略，完整名称可通过 title 查看；文件名本身也是下载链接时，应与右侧操作指向同一下载 URL，避免嵌套链接。
- `ready` 文件：右侧细小下载图标加“下载”。不做整行点击，以免与文本选择、键盘操作冲突。
- `expired` / `missing`：右侧分别显示“已过期”/“文件已失效”，无下载链接；弱化但不降低到难以辨认。
- 完整文件名、文件大小、交付时间、到期时间可放入行的 title/已有 tooltip；缺失或非法时间不显示 Invalid Date。不要只用悬停传达不可下载状态。
- 窄屏下文件名可收缩，必要时隐藏独立大小列（详情保留）；下载入口和状态不能被挤出卡片，不产生水平滚动。
- 图标优先采用项目已有并已验证可导出的图标，不新增依赖，不盲目引用宿主不存在的导出。

## 4. 交互与状态

| 条件 | 行为 |
| --- | --- |
| 1–4 个文件 | 展示全部，无展开入口 |
| 大于 4 个文件 | 初始显示 4 行；底部“全部 N 个文件”按钮，带向下箭头 |
| 点击展开 | 显示全部，按钮变为“收起”及向上箭头；再次点击回到 4 行 |
| 列表轮询更新 | 更新汇总、行内容和 N，保持当前展开状态；同 ID 不重复，同名不同 ID 均保留 |
| 切换 nodeId/sessionId | 重置为收起；不得短暂显示其他会话的旧列表，迟到响应不得串会话 |
| 点击可用文件下载 | 沿用原生链接与服务端文件名；不新增 download 属性覆盖中文文件名 |
| 文件过期或缺失 | 根据节点返回的 state 展示，不仅凭本机时钟自行判定 |
| 无文件且工具可用 | 保留现有简短交付引导，不出现“已交付 0 个文件”的假列表 |
| 工具不可用 | 保留现有检查/升级提示，不能静默隐藏原因 |
| 能力未知或正在探测 | 保持现有行为；不要误报工具不可用或伪造有文件 |
| 列表读取失败 | 保留已读取文件及现有区域错误提示；不能把失败当作空列表 |

重要修正：前期讨论提到过“下载失败/重试下载”。现有原生浏览器下载无法可靠回传最终结果，所以本期不实现自定义下载中、成功、失败或重试状态。浏览器负责下载过程；不要把点击链接标成下载成功，也不要为此改成整文件 Blob 缓冲。如将来确需状态反馈，另行设计传输方案。

展开按钮必须是可键盘操作的原生 button，包含 `aria-expanded` 与有效的 `aria-controls`，保留可见焦点。若使用 HTML details/summary，提供同等可访问性。收起的文件不可通过 Tab 聚焦；不要用纯透明度隐藏。

## 5. 实施顺序

1. 只读检查实际工作区的 AGENTS.md、现有改动、产物相关源码与测试；此文档不是覆盖当前源码的依据。
2. 先针对汇总、4 行截断和原有状态补充/调整有意义的测试，确认旧布局相关断言需要改变，再实现最小组件改动。
3. 优先复用 `ArtifactList` 入口及 `ArtifactCard` 导出，后者可以成为紧凑文件行；不要只为改样式新增多层抽象。独立导出是否保留应检查全部调用点。
4. 接入汇总信息、展开收起、会话身份重置。可以给 `ArtifactList` 增加会话组合 key，或在组件内部处理身份变化，选最小可靠方式。
5. 在原主题变量上完成紧凑样式，检查长文件名、窄屏、浅色主题和键盘焦点。
6. 执行下述验证，整理实际变更、命令结果与截图；仅在明确授权后提交、部署或重启服务。

## 7. 与“卡片没有显示”问题的关系

本期布局改造不等于修复所有“没有卡片”的场景：无 `deliver_file` 登记、能力不可用、列表请求失败、运行实例未加载源码都可能影响显示。

若指定会话仍没有卡片，实施者先确认该会话的真实 `listArtifacts` 响应和前端能力状态；有产物但没渲染可在本期修复。涉及模型交付行为、node/coordinator 缺陷或需远程发送测试提示时，报告证据并单独确认范围。不得自行向真实远程会话发提示，不读取或输出凭证。
