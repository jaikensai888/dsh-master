# 「关注」会话完成蓝点设计

## 用户看到的变化

- 「关注」列表中的会话成功完成一轮并且结果待查看时，在行尾现有状态圆点的位置显示实心蓝点。提示和无障碍名称采用「已完成，待查看」，英文采用 `Completed, unread`。
- 进行中优先显示现有运行圆点。先前尚未查看的成功轮次仍可在运行结束后恢复蓝点。失败、取消和断线本身均不产生完成提醒。
- 前台打开会话并成功加载对应结果后消除蓝点。会话已在前台且成功收到该轮结果时直接视为已查看。从关注行、普通会话列表或搜索结果进入，都按相同规则处理。
- 刷新页面后保留未查看状态。已查看过的轮次不再亮点，后续成功完成的新轮次可再次提醒。

## 采用的方案

本机会话复用宿主普通列表的 `completionUnread` 及其已读行为。远程会话通过现有按节点轮询取最近一次成功完成的事件序号，通过已打开面板的会话流确认用户实际收到的事件序号。两者使用同一种蓝点样式。远端列表轮询能发现两次请求之间完成的短任务，单看 `running` 无法区分成功、失败和取消，也会漏掉短任务。

远程沿用关注记录的浏览器存储范围，按 Coordinator 来源、节点和会话隔离。首次获得完成摘要时，以当时的完成序号为基线，避免初次关注或升级时补亮历史蓝点。旧节点或摘要不可用时会话按原有方式显示及打开，一旦恢复有效摘要就与保留的基线比较。远程提醒在打开「关注」或其前台轮询拿到新摘要后更新。

范围限于「关注」会话行。列表的关注时间排序沿用现有逻辑。
