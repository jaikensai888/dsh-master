# 跨工作区「关注」设计

2026-11-09 · dsh-master 首版开发交接

## 目标与范围

用户需要从同一处打开手动标记的本机和远程会话，继续跟进分布在多台机器上的任务。用户已确认首版的关注记录存于当前浏览器。实现范围为 dsh-master，沿用现有会话导航、权限和远程接口。「最近」、跨浏览器同步、通知、全节点扫描和自动轮询留在后续范围。

## 用户操作

| 位置 | 行为 |
| --- | --- |
| 工作区下拉 | 在「本地」附近提供「关注」，即使远程不可用也可进入。选中后用同一个侧栏位置显示关注列表。 |
| 会话行 `…` | 本地工作区分组、平铺会话行和远程会话行均提供「关注 / 取消关注」。仅正式会话可以添加，空白的新会话沿用原行为。远程归档能力缺失时，正常可打开的会话依然可以关注。 |
| 关注列表 | 每条显示标题、机器和工作区。无工作区使用「未分组」，本机机器标签用「本地」。默认按添加关注时间倒序，同时间保持稳定顺序。重命名、会话活动和刷新均保持顺序。 |
| 打开与切换 | 点击可用条目，右侧按原有本地或远程路径打开会话，左侧留在「关注」并高亮当前条目。在该范围里打开本地或远程会话都不出现「当前会话在其他工作区」提示。 |
| 取消关注 | 从来源行或关注行的菜单即时取消。右侧已打开的会话保持打开，取消仅删除浏览器里的关注记录。 |
| 搜索 | 在「关注」范围内用现有搜索入口按标题、机器、工作区筛选关注条目。进出「关注」时清除搜索词并取消旧搜索请求，本地正文搜索继续按现有逻辑工作。 |
| 空状态 | 没有关注时提示「在会话的 ··· 菜单中选择关注」。筛选无结果时显示独立提示。 |

顺序、搜索范围和下方的归档策略是本方案采用的首版默认值。

## 记录与来源

- 在侧栏视图 store 中增加关注记录与 `following` 浏览范围。沿用 `dsh.workspace.view.v5` 的兼容方式，为旧快照补齐字段，保留原有排序、折叠和选中范围。关注记录独立于工作区分组和排序账号的清理逻辑。
- 本机用 `sessionId` 标识，远程用 Coordinator 来源、`nodeId`、`sessionId` 标识。本机和远程分别命名。Coordinator 来源采用现有状态返回的无凭据地址 `MasterCoordinatorFacts.url`，用于隔离同一 dsh-master 浏览器中曾连接的不同 Coordinator。每次进入「关注」或手动刷新都核验来源。核验期间暂停打开远程条目，核验后只允许使用与当前来源匹配的条目和摘要。旧来源条目保留并标为不可用，切回后重新核验。
- 每条仅保存身份、关注时间以及渲染所需的最后已知标题、机器名和工作区名称。使用新鲜的会话与工作区摘要更新这些显示字段。会话正文、文件、路径、凭据和运行状态留在原数据源。重复关注同一身份只保留一条，取消后重新关注会生成新的关注时间。
- 关注列表以浏览器记录为入口。本机与已加载远程摘要用于核验及更新显示，刷新失败时保留最后已知摘要。列表里暂时找不到某条记录时也保留关注，用户可以显式取消。

## 加载与状态

进入「关注」和手动刷新时，复用 `RemoteSection` 的节点名册、按节点会话缓存及请求协调逻辑。只请求有关注记录且当前可路由的远程节点，同一节点多条关注共用一个请求，采用有上限的并发。离开视图、刷新重叠或切换 Coordinator 时，旧请求不得覆盖新来源或新刷新结果。侧栏保留一个远程数据所有者。本机会话直接使用现有订阅。

| 来源状态 | 关注行表现 |
| --- | --- |
| 当前来源确认可用且能找到会话 | 使用最新摘要，允许直接打开。 |
| 正在确认来源或拉取目标节点 | 先显示已保存摘要，状态为「加载中」。 |
| 节点离线、Coordinator 连接失败、节点撤销或来源变化 | 保留条目，显示对应的「离线」或「来源不可用」，禁用打开，允许取消关注。 |
| 单个节点列表请求失败 | 保留该节点的条目，显示「加载失败」，可手动刷新。其他来源的条目正常工作。 |
| 刷新成功但没有返回会话，或确认会话已归档 | 分别显示「暂未找到」和「已归档」，保留条目、禁用打开并允许取消。恢复后按刷新结果更新。归档能力缺失时沿用该节点现有打开行为。 |

归档以明确的归档数据为准。空名册、失败的请求和过时缓存只用于提示可用性，均不能删除关注记录。网络恢复后，重新进入或刷新「关注」即可重新核验。

首版的来源隔离以侧栏成功核验的 Coordinator 为边界。现有远程会话请求由服务端读取当前 Coordinator 配置，来源核验与会话请求之间仍可能遇到配置变化。要覆盖这种并发切换，需要在服务端将会话请求绑定到确认的来源，属于独立的协议工作。

## 开发入口

| 入口 | 职责 |
| --- | --- |
| `src/workspace/stores.ts` | 持久化关注、身份去重、旧快照兼容。 |
| `src/workspace/WorkspaceNodeChooser.tsx`、`browse-scope.ts`、`locales.ts` | 入口、标题、筛选与中英文文案，兼容折叠侧栏及键盘操作。 |
| `src/workspace/rows/WorkspaceBrowser.tsx`、`src/workspace/rows/Rows.tsx` | 本地会话菜单、跨来源列表、搜索和浏览范围。 |
| `src/workspace/RemoteSection.tsx`、`src/workspace/contract/slots.ts` | 远程菜单、来源验证、按节点加载和数据接线。已有远程会话菜单目前受归档能力控制，新增关注动作应独立判断。 |
| `src/client/selection.ts` | 复用现有会话打开逻辑。调用方决定是否调整侧栏浏览范围。 |

关注列表组件、行样式与数据接线由开发 Agent 按现有结构选择。现有本地置顶、远程归档和会话权限各自保留原有语义。

## 验收

1. 关注一个本机会话和两台远程机器上的会话，三条都出现在同一个列表。两台节点即使返回相同 `sessionId` 也各自打开正确的会话。确认本地和远程之间交替打开时，侧栏一直处于「关注」。
2. 刷新浏览器后记录与顺序仍在。使用旧版侧栏快照启动时，原有设置可用。重复标记不产生重复行，取消关注不关闭会话。
3. 让一台已关注的节点离线或列表加载失败，其余条目仍可用。离线条目在重载后仍有上次标题，能够取消，恢复后可刷新打开。对归档和暂未找到执行同样的记录保留检查。
4. 切换 Coordinator 至返回同一 `nodeId` 与 `sessionId` 的另一来源，再进入或刷新「关注」。核验期间远程条目暂停打开，确认新来源后旧条目标为不可用且摘要保留。切回并重新核验后可以打开旧条目。
5. 进入或刷新「关注」时，仅加载当前来源中需要的节点。验证同节点多个关注只触发一次列表请求，以及切换范围、快速刷新时旧响应不会覆盖新状态。
6. 在中英文环境检查下拉、菜单、空状态和错误文案。确认关注内筛选不触发本地正文搜索，现有本地/远程浏览及归档可继续使用。
