# 远程会话内容对齐本地设计

## 目标与范围

同一个会话从本地或远程打开时，用户可以在相同的阅读顺序里找到回合状态、助手回复、执行过程、工具结果和文件。以实际运行的 DSH 桌面版本为基准，范围覆盖会话正文、回合过程、工具卡、文件变更和交付文件区域。远程连接、输入框、审批、提问、文件访问继续使用现有远程链路。

## 已知差异

远程 `conversationItems()` 把停止和失败回合的过程行留在 `visible`，而 `TurnProcess` 会把 `visible` 作为正文输出。用户截图中「已停止」下方反复出现过程行，与该分支一致。成功回合已具备过程折叠、最终回复及文件变更汇总。底部「本次会话的交付文件」由独立的 `ArtifactList` 渲染。

## 对齐规则

- 优先解决停止和失败回合的过程堆叠。正式实现前记录本地对运行中、完成、停止、失败四种状态的默认可见内容，并用这一组观察作为远程验收标准。
- 过程应可展开查看，回复保留原始文案和位置语义。停止后的部分回复仍可读，失败原因仍可见，已有等待用户操作保持可达。真实用户插话保留时序。上下文注入不拆分回合。
- 命令、通用工具和文件变更先对齐摘要、详情及成功或失败的表达。文件变更和交付文件分别基于原有数据来源，避免把执行意图算成已修改、或把修改过的文件算成交付文件。
- 优先复用当前桌面版本支持的公开组件、注册表或呈现接口。此前检查的导出未发现可单独挂载的正文组件。如果仍没有适用的公开入口，在 dsh-master 现有模型和组件内对齐对应行为。历史记录信息不全时保留原有记录及兼容展示。
